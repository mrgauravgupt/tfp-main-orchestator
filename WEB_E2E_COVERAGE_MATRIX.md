## 2. Coverage Criteria & Definitions

1. **`FULLY COVERED`**: The test executes the complete user flow end-to-end through real browser UI actions, interacts with live backend services (including background workers where applicable), and asserts the visible final UI state, database persistence, and system outcomes.
2. **`PARTIALLY COVERED`**: The test covers happy-path navigation or API execution, but skips negative branches, form validation errors, boundary inputs, or post-action UI state assertions.
3. **`NOT COVERED`**: The capability or state transition is present in the application code, but no E2E test exercises it.
4. **`COVERED BUT WEAK/FLAKY`**: The test exists but uses artificial sleeps, bypasses UI via synthetic HTTP headers (`x-test-image-moderation-outcome`), mocks critical network responses (`page.route`), relies on generic assertions (`body toBeVisible()`), or mutates the database mid-test.
5. **`NOT TESTABLE WITH CURRENT SETUP`**: Scenarios that require external production infrastructure (e.g., third-party SMS gateways, live Cloudflare Edge headers, OAuth identity provider popups without a sandbox).
