# Browser UI QA

Before testing, identify routes, expected states, authentication/seed requirements, target environment, and evidence-based breakpoints. Verify loading, empty, success, error, permission, navigation, forms, keyboard/focus, semantic labels, responsive overflow, typography/tokens, console errors, failed network requests, hydration warnings, localisation, and long-copy behaviour as relevant.

Record route, viewport, state, observation, console/network result, and confidence. Do not claim physical mobile-device proof from desktop emulation.
