03 / Setup playbooks

From dashboard click to revocation.

Open a playbook, complete its steps, and record only the variable name—not its value—in tickets or QA notes.

01

Cloudflare · secure front door

Validate now

Current OCI path

  1. Use the existing tfp-oci-uat tunnel on tfp-a1-free-2ocpu-12gb.
  2. Keep uat.tfpphotographers.com mapped only to http://localhost:8080.
  3. Access application TFP UAT must retain policy Approved UAT testers.
  4. Allow only explicit QA emails; use email OTP; current application session duration is six hours; default deny.
  5. Keep OCI and host firewalls closed for all application/database ports. Keep SSH key-only and separately restricted.

The Tunnel token is a secret. Rotate it by installing the replacement on OCI, verifying a healthy connector, then ensuring the previous token is invalid.

Least privilege + verification

  • Do not use the Cloudflare Global API Key.
  • Visit in a signed-out browser: the Access login must appear.
  • Test an allowed email, a denied email, logout, and expiry.
  • Verify direct origin ports 4000, 5432, 7001-7004, and 8080 are unreachable.
  • Confirm the connector hostname is tfp-a1-free-2ocpu-12gb and the origin IP is 161.118.161.98.

02

Backblaze B2 · storage

Validate now

Create and scope

  1. B2 Cloud Storage → Buckets: create/confirm UAT public and private buckets.
  2. Application Keys → Add a New Application Key.
  3. Restrict to the exact bucket(s) and only required read/write/list/delete capabilities.
  4. Record S3 endpoint and region from Backblaze—not a guessed hostname.
  5. Configure CORS only for the exact UAT origin if browser-direct access is required.

B2_ENDPOINT · B2_ACCESS_KEY_ID · B2_SECRET_ACCESS_KEY · B2_BUCKET_NAME · B2_PRIVATE_BUCKET_NAME · B2_REGION · B2_PUBLIC_URL · B2_CORS_ALLOWED_ORIGINS

Verify + rotate

  • Upload, read, and delete a disposable object through the application.
  • Confirm private objects cannot be fetched anonymously.
  • Confirm allowed origin works and an unlisted origin fails.
  • Create replacement scoped key, deploy both halves, test, then revoke old key.

04

Internal secrets · service trust

Generate / align

Generate independently

Run openssl rand -base64 48 once for every unrelated purpose. Never reuse JWT, cookie, OAuth, upload-signing, moderation, or collage secrets.

JWT_SECRET · COOKIE_SECRET · OAUTH_STATE_SECRET · OAUTH_TOKEN_ENCRYPTION_SECRET · STORAGE_LOCAL_UPLOAD_SIGNING_SECRET

Store values only in the approved VPS environment file or secret manager with owner-only permissions.

Required alignment exceptions

  • MODERATION_REMOTE_AUTH_TOKEN in the app must match the moderation service’s AIP__SECURITY__INTERNAL_API_KEY (and the intended AIP_INTERNAL_API_KEY alias where configured).
  • COLLAGE_SERVICE_API_KEY must match between caller and collage service.
  • Rotate shared secrets with an overlap/two-key strategy if supported; otherwise coordinate a short maintenance window.

Never paste a secret into chat, source control, screenshots, tickets, shell history, or this guide.

08 / Secret handling policy

Keep the blast radius small.

Store

Use the deployment secret store or root-owned VPS environment files with least-readable permissions. Keep UAT separate from production. Never commit .env.*.local.

Transmit

Never share values in chat, tickets, screenshots or email. Prefer provider invitations and a password manager. Avoid command-line arguments and history for secrets.

Rotate

Record owner, purpose, scope, creation and review date. Prefer create → deploy → verify → revoke. Revoke immediately on suspected disclosure and inspect provider audit logs.
